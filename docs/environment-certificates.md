# Observed project environment and import certificates

This development contract preserves evaluated source order without accepting a stale project when an ambient build input or an SDK import hook changes. It runs only during explicit project preparation. Native validation is lazy, before a project-wide proof; startup does not run MSBuild or read source bodies.

The current producer/consumer contract is `environmentCertificate.version:4` and `contract:"dotnet-msbuild-observed-v4"`. Version3 is rejected because it omitted culture-dependent glob selection. The initial v4 profile is Linux x64, SDK10.0.400, runtime10.0.11 and glibc2.41, with one installed SDK/runtime/fxr choice. SDK100, SDK11, other platforms and the requested Nix workflow are not yet certified. This is a bounded evaluation contract, not a general interpreter of arbitrary MSBuild dependencies.

For each selected project the helper performs its ordinary property/item evaluation and additional event-traced SDK/TFM-selection and final design-time Compile invocations. A co-located `FSharpNavigator.EvaluationLogger.dll` requests the actual pinned MSBuild property/import events. The JSON `-getItem`/`-getProperty` path did not initialize custom loggers in our runtime probe, so it cannot substitute for those traced invocations. This adds explicit preparation work; it is excluded from native warm-query timing but must be included in end-to-end setup cost.

The helper records names read from inherited environment and names read while absent. Initially absent property references in actual imported XML supplement negative events, because an absent execution-phase `OtherFlags` produced no event while its present form did. Each selected inherited value is represented only by SHA256 or `"missing"`. Empty and missing differ. Conflicting case-insensitive ambient names reject. Fixed helper overrides are part of the evaluation policy, and properties explicitly global in every relevant observed invocation are excluded from ambient dependencies. Unused present PATH/PWD/editor variables are not hashed merely because they exist.

Early resolver/host selectors have a separate bounded list, including `FSHARP_NAVIGATOR_DOTNET`, SDK resolver overrides and root/roll-forward settings. The selected dotnet host and actual SDK/logger/helper bytes are ordinary input fingerprints. Custom wrapper executables or additional resolver folders refuse reusable certification; a wrapper could change the child environment independently of the parent's snapshot. An ordinary Nix launcher which runs the real dotnet host is distinct from an arbitrary `FSHARP_NAVIGATOR_DOTNET` wrapper override.

Culture is observed inside each actual MSBuild process without changing it. The logger records current/UI culture, sort version, runtime identity and libc LC_MESSAGES. The initial profile requires libc C/POSIX, where the pinned ICU implementation selects its default locale from the certified environment. Mandatory startup selectors preserve missing, empty and present states and exact POSIX spelling; noncanonical case aliases reject even though ordinary MSBuild properties remain case-insensitive. Unreviewed globalization, locale archive, dynamic-loader and early MSBuild feature overrides fail closed.

The globalization certificate binds actual runtime/ICU/loader files, loader cache and runtime configuration, all relevant candidate ICU bytes, immediate selection-directory entries and raw ancestor/leaf symlink states. New version directories, higher-priority ICU candidates, rewritten candidate bytes or retargeted paths invalidate reuse. Actual coreclr contains the pinned statically linked globalization implementation; an unmapped standalone shim is not invented as a loaded module. Loaded-file hashes alone would miss later selection changes. These checks run on first model use, with same-session identity validation thereafter; their preparation and first-use cost must be measured separately.

Native model validation now uses a bounded digest generation shared by project input hashes and globalization file rows. It caches actual SHA256 results, never expected values or a certificate-validity decision. Every alias is opened as a nonblocking regular file and checked against its descriptor before and after use; every expected hash is compared independently. Up to128 retained descriptors prevent inode recycling while cached; LRU eviction forces a later reread. A changed observed inode, error or cancellation poisons the generation, and the next validation starts empty. Unsupported physical-identity platforms do not reuse digests. All selector, directory, symlink and outer before/after snapshot checks remain unchanged. Counters distinguish requested payload bytes from actual hashing bytes and reuse hits. This is not an atomic filesystem snapshot or persisted trust. See `docs/review/digest-generation-review.md` for independent mutation and measured component evidence; the later narrow factory repair has its own scoped review and coverage regression, so certificate correctness is not general inference acceptance.

Property assignment events maintain the import-time property state. Every actual import path and negative Exists probe is captured, including trusted SDK imports. `MSBuildThisFile`, `MSBuildThisFileName`, extension, full path and directory variants are derived from the defining import file. Wildcard import roots receive filename-only membership witnesses even when no file currently matches. `extensions:["*"]` covers extensionless ImportBefore/After hooks; suffix-specific domains remain narrower. Existing directories use the distinct input sentinel `sha256:"directory"`. A directory's contents are represented by a membership certificate when required, not by that existence sentinel.

Plain explicit source lists do not gain an unrelated source-directory dependency. A new uncompiled `.fs` outside a relevant source/import domain should not invalidate them. A new `obj/P.fsproj.extra.targets`, a glob-matched source, or an extensionless SDK hook can change source order and must invalidate the old model. Native watchers observe the nearest existing ancestor of missing domains without recursively crawling the whole SDK. The optional semantic snapshot validates the same environment/membership contracts independently, in addition to source and binary hashes.

Unknown custom tasks, item expressions, dynamic resolver behavior and arbitrary IO/environment property functions remain unsupported. The narrow pure-function allowance covers String.Copy with Length or numeric Substring and MSBuild.Modulo with literal/property arguments. Ordinary argument reads remain dependencies. These were the only static functions found in the actual Grace non-SDK import set besides already validated analyzer-only String.Copy/IndexOf forms.

Evidence is deliberately versioned. The earlier10-case `environment-certificate-v1.json` passed observed-environment replay but did not prove SDK wildcard closure. Independent review rejected helper8290 and b23a for additional import-domain/precision issues. Helper80e5 remains a historical captured-source v3 diagnostic. Later culture probes rejected the entire v3 reuse contract despite its earlier environment/import controls. Helper09f011 and source341bba introduce the v4 profile; actual culture initial/stale/fresh, selector-case and bidirectional version controls passed against aligned native85d1, which requires the libc-bootstrap/locale-path checks. Genuine model/source artifacts are retained with `test-results/recovery/globalization-certificate.json`; independent review is recorded separately. None of these component results establishes full Ionide parity or the requested monolith speedup.
